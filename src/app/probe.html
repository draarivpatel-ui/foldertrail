Drop probe (M0)

A local test page (decision B30). It shows only names relative to what you drop, sizes, and what the intake found. It reads no file contents except the first 4 bytes of a loose file, and a backup's table of contents.

The probe script did not run. Browsers refuse module scripts on file:// pages, so serve the repository folder over http://127.0.0.1 instead: in Terminal, in the repository folder, run python3 -m http.server 8000 --bind 127.0.0.1, then open http://127.0.0.1:8000/src/app/probe.html.

What to try in each browser (Safari, Chrome, Firefox)

  1. In Finder choose Go > Go to Folder…, open ~/Library/Application Support, make a folder Probe/Database/4.8 with empty files AllData.gdb, FolderData.gfi and a TrackSegments folder, then drag 4.8 (and separately Probe) onto this page.
  2. Pick the same folder with "Choose folder". Note the exact words of any dialog the browser shows.
  3. Drag a package onto the page. A folder renamed to end in .bclibrary is probably only a package on a Mac where BaseCamp is installed (a guess: the app that owns an extension declares it a package), so also try a package that exists anyway, such as an app from /Applications.
  4. Compress a folder in Finder (right-click > Compress), then drop the .zip and pick it with "Choose files". Rename a copy to end in .Backup and try that too.
  5. Copy the structure-only summary below into the M0 log. It holds no file names.
